# 小柒本地备份

一个跑在自己电脑上的**文件夹备份工具**，Windows 平台，带系统托盘常驻、网页设置界面。
两种备份模式可以同时开：**每一次都留一份完整副本**（能回到过去），**外加一块和源保持一致的镜像**（省空间）。

> 界面是浏览器打开的：程序在本机 `127.0.0.1` 上起了一个只面向自己的小服务，
> 浏览器连的就是它。托盘图标才是程序本体，关掉浏览器不影响备份。

## 为什么会有这个工具

备份工具很多，但常见的两类各有短板：

- **同步类**（FreeFileSync、Syncthing…）实时性好，但历史版本弱；
- **备份库类**（restic、Kopia、Duplicati…）历史强，但对非技术用户不友好——
  想从里面"随手捞一个文件出来"得先学一套概念。

这个工具选的路线是**最笨但最直观的一种**：

> 每次备份 = 在备份文件夹里生成一个**带时间的完整文件夹**。
> 你想找哪天的东西，直接打开那天那个文件夹就行，不用任何工具、不用恢复流程。

代价是占空间（N 份 = 源大小的 N 倍），所以配了"只保留最近 N 份"来自动清理。

## 两种备份模式

两种模式**可以同时开**，各自有独立的定时 / 变动触发。

| | **完整备份** | **镜像备份** |
| --- | --- | --- |
| 产出 | 每次一份 `<备份夹名><年月日时分>` 的完整文件夹 | **只有一份** `<备份夹名>-镜像`，建好就一直复用 |
| 做法 | 把源里所有内容拷进去 | 只同步有变化的内容 |
| 源里删掉的文件 | 不影响已有的备份 | **从镜像里也删掉**（真镜像） |
| 清理 | 「文件留存」自动只保留最近 N 份 | 不需要（永远只有一份） |
| 适合 | 需要历史、需要"回到某一天" | 需要一块随时可用的最新副本 |

**触发方式**（每种模式各一套）：

- **定时触发**：每 N 分钟，或每天固定时刻。
- **变动触发**：每 N 分钟扫描一次源文件夹，把「相对路径 + 大小 + 修改时间」列成指纹跟上次比对，
  **有变化才备份**。不依赖任何文件监听组件。

## 恢复

任务卡片上点「恢复」：

- 左边列出各份完整备份（新的在上），右边是里面文件的树，**文件夹默认合上、点开才展开**；
- **整批恢复**：整个备份文件夹复制到**源文件夹旁边同一层**（不放进源里——放进去下次备份会把它一起备份，越滚越多）；
- **单项恢复**：放回源文件夹里原来的位置，**遇到同名文件自动改名另存**（`原名_恢复<时间>.扩展名`）；
- **任何情况下都不覆盖你现有的文件**，恢复完自动打开结果所在文件夹。

## 快速开始

### 用源码跑

```bash
python src/main.py --open-ui      # 启动并打开设置界面
python src/main.py                # 静默启动（只进托盘，适合开机自启）
```

界面上：**添加任务 → 选源文件夹和备份文件夹 → 勾选要用的备份模式 → 保存并应用**。

### 打包成单文件 exe

```bat
python -m PyInstaller --noconfirm --onefile --windowed ^
  --name "小柒本地备份" ^
  --add-data "<项目目录>\src\ui;ui" ^
  --paths "<项目目录>\src" ^
  --hidden-import pystray._win32 ^
  --distpath "dist" --workpath "_build\work" "src\main.py"
```

产物 `dist\小柒本地备份.exe`（约 27 MB，**已内含 Python 运行环境**，拷到别的 Windows 电脑双击即用）。

几个容易踩的点：

- `--add-data` 要写**绝对路径**；目标名必须叫 `ui`（代码从 `sys._MEIPASS/ui/index.html` 取界面）。
- **重打之前先关掉正在运行的 exe**，否则文件被占用、覆盖不了。
- `--windowed` 没有控制台，出错看不到提示，排查请看 `%APPDATA%\XiaoQiBackup\logs\`。

## 目录结构

```
src/
  config.py    配置模型 / 默认值 / 旧配置迁移 / 日志
  engine.py    备份引擎：完整备份、镜像、清理、恢复、变动指纹
  triggers.py  定时触发 + 变动扫描（每 N 分钟比对指纹）
  trayapp.py   控制器 + 系统托盘
  webui.py     本机 HTTP 服务 + 系统文件夹选择框
  main.py      入口：单实例检查 → 起界面 → 进托盘
  ui/index.html  设置界面（单文件，原生 JS，无构建步骤）
tools/
  selftest.py   引擎自测
  uitest.py     端到端自测（起真服务打接口）
  uitest_ui.js  界面行为自测（jsdom，真的点界面）
  uipreview.py  界面预览（造演示数据，看效果用）
  pickcheck.py  检查系统文件夹选择框能不能弹出
```

数据位置：配置与日志都在 `%APPDATA%\XiaoQiBackup\`（可用环境变量 `XQB_DATA_DIR` 改到别处，
自测就是靠它隔离的）。

## 自测

```bash
python tools/selftest.py       # 引擎
python tools/uitest.py         # 端到端（HTTP 接口）
node tools/uitest_ui.js        # 界面行为（需要 npm install jsdom）
```

三套测试各管一层：**引擎算得对不对 / 接口通不通 / 界面点得动吗**。
每次运行都会新建独立的 `_t\<时间戳>_xxx` 目录，不会动你的正式数据。

界面行为测试（jsdom 那套）是这个项目里最有价值的一层：它能抓到"接口全绿但界面没法用"的问题，
比如**未保存的编辑被定时刷新冲掉**、**该收起的面板没收起**。

## 安全底线

备份工具的第一原则是**不能让自己成为丢数据的原因**。代码里有几条硬约束：

1. **清理旧备份时，只删带标记文件的文件夹**（每个备份文件夹里都有一个 `.xqb-*.json` 标记）。
   你自己手动放进备份目录的东西，**一律不碰**。
2. **排序与清理按标记里的实际创建时间**，不按文件夹名字——
   名字只精确到分钟，同一分钟内清理释放掉的名字会被复用，按名字排会把刚建好的当成最旧的删掉。
3. **恢复永不覆盖**：整批放到源旁边、单项重名就改名另存。
4. **写文件走临时文件 + `os.replace`**，中断不会留下半个文件。
